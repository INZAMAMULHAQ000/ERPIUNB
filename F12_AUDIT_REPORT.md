# F-12 Module Audit — Accounting Period & Year-End Closing

**Audit date:** 2026-08-26 · **Method:** 21-agent adversarial code audit (11 areas, every reported gap re-verified repo-wide) · **Spec:** F-12 module.md (27 steps)

## Verdict

F-12 is **substantially built but NOT complete**. The database schema, all ten screens, and both engines exist, and much of the wiring is genuinely production-grade — but two core write-paths fatal at runtime, the closed-period lock has payroll bypass holes, and several spec-mandated mechanisms (attachments, checklist configuration, per-account opening-balance verification, adjustment-into-closed-period carve-out) are absent.

### Showstoppers (verified by live execution)

1. **Year-End Close crashes — always.** `generateVoucherNo()` is defined ONLY in root `helpers/finance_helpers.php`, which no F-12 entry point loads. `closing/index.php:8` and `YearEndClosingService.php:295` load `modules/finance/helpers/finance_helpers.php` instead — a file with ZERO top-level functions (`function_exists('generateVoucherNo') === false`, verified via CLI). The call at `YearEndClosingService.php:297` throws an uncatchable PHP `\Error`, so **Execute Year-End Closing can never succeed**.
2. **Closing Adjustment creation crashes too.** Same defect at `adjustments/create.php:51`; the surrounding `catch (Exception)` at line 74 cannot catch a `\Error`. No closing adjustment can ever be created.
3. **Payroll bypasses the period lock.** `payroll_finance/postings/process.php:110-131` and `payroll_finance/payments/process.php:121-147` INSERT into journal_entries directly with status='posted' using a client-supplied posting_date — they never touch PostingEngine, so postings into CLOSED periods are possible through these UI-reachable paths.
4. **Depreciation posting is dead code.** `fixed_assets/depreciationservice.php:585` requires nonexistent `modules/finance/PostingEngine.php` and line 615 calls an undefined `postJournalEntry()` method — depreciation can never post to GL, so it also has no period-lock enforcement point. `payroll/postings/post.php:16` fatals on a broken require path for the same reason.

Remaining items are minor: the Open->active rename, missing UNIQUE on year_code, incomplete FK coverage on secondary reference columns, and reliance on a manual per-module setup script since neither setup.php nor config/schema.sql provisions these tables.

**Reported gaps:**
