Implement **AI F7 — AI Navigation Intelligence** in the existing Core PHP + MySQL ERP.

### Objective

Allow the AI Assistant to understand the ERP navigation structure and guide users directly to relevant pages.

The AI should be able to:

- Answer where a feature/page is located.
- Understand natural language navigation requests.
- Provide direct ERP links.
- Suggest relevant destinations.
- Navigate the user to a page only after explicit user interaction.

Examples:

> Where do I create a supplier?

> Take me to purchase orders.

> Where can I manage AI providers?

> I want to see purchase requisitions.

This step introduces **navigation capability only**.

Do NOT allow AI to read ERP business records.

Do NOT allow AI to modify anything.

Do NOT implement generic tool execution yet.

---

# 1. Create Central Navigation Registry

Create a centralized AI-readable navigation registry.

Do not duplicate the entire sidebar manually if the existing ERP already has a navigation/menu configuration.

Reuse or extend the existing navigation configuration wherever possible.

Each AI-navigable destination should contain normalized metadata such as:

- unique identifier
- module
- parent section
- page name
- display name
- description
- URL/path
- keywords
- synonyms
- required permission(s)
- active status

Conceptual example:

```php id="tqbl48"
[
    'id' => 'procurement.suppliers',
    'module' => 'procurement',
    'section' => 'suppliers',
    'name' => 'Suppliers',
    'description' => 'Manage suppliers and vendor information',
    'url' => '...',
    'keywords' => [
        'supplier',
        'suppliers',
        'vendor',
        'vendors',
        'vendor management'
    ],
    'permissions' => [
        '...'
    ]
]
```

Adapt to existing Core PHP architecture.

---

# 2. Navigation Registry Must Respect Permissions

When building navigation context for the AI:

- Only include destinations the current user is authorized to access.
- Do not reveal hidden/restricted ERP pages.
- Do not suggest inaccessible pages.
- Permission validation must also occur when generating navigation actions.

Do not rely only on the frontend.

---

# 3. Navigation Search Service

Create a reusable navigation search service.

It should accept a natural-language query and return relevant accessible destinations.

Implement an initial deterministic matching system using:

- Exact name match
- Keyword match
- Synonym match
- Partial match
- Module match

Do NOT use the AI provider itself to search the navigation registry.

The AI model can reason over the available navigation context, but destination matching should also have deterministic server-side support.

Example logical function:

```text id="4dtv4d"
searchNavigation(query, userContext)
```

Return only:

- Accessible destinations
- Relevant results
- Safe navigation metadata

Rank results by relevance.

Keep the implementation simple and extensible.

---

# 4. Provide Navigation Knowledge to AI

When building the AI request, include a compact representation of accessible navigation destinations.

Do not send unnecessary internal metadata.

The AI should understand:

- Page names
- Module hierarchy
- Purpose
- Available navigation URLs/identifiers

Example conceptual instruction:

```text id="a8o9c4"
Available ERP destinations for this user:

Procurement
- Suppliers: Manage supplier information
- Purchase Requisitions: Create and manage purchase requisitions
- Purchase Orders: Manage purchase orders

AI
- Providers: Configure AI providers
- Models: Manage AI models

When directing a user:
- Only use destinations listed here.
- Never invent URLs.
- Never claim a page exists if it is not listed.
```

Use compact context to avoid unnecessarily large prompts.

---

# 5. Structured Navigation Suggestions

Do not depend only on free-text AI output.

Create a structured navigation suggestion format.

Conceptually:

```json id="u0c2jg"
{
    "navigation": [
        {
            "destination_id": "procurement.suppliers",
            "label": "Open Suppliers",
            "reason": "Manage supplier records"
        }
    ]
}
```

The provider response must be validated before being used.

If the current provider/model supports structured output, use it where appropriate.

Otherwise:

- Parse a controlled response format safely, OR
- Use deterministic backend navigation matching.

Do not execute arbitrary URLs generated by the AI.

---

# 6. Navigation Action Validation

Before displaying or allowing navigation:

1. Validate destination ID against the server-side registry.
2. Validate the destination is active.
3. Validate the user still has permission.
4. Resolve the URL server-side.
5. Send only validated navigation data to frontend.

Never directly trust:

- AI-generated URL
- AI-generated JavaScript
- Arbitrary route string

The AI should select a destination identifier, not invent executable navigation paths.

---

Enhance AI Assistant responses with navigation cards/actions.

Example:

```text id="b14plr"
You can manage suppliers here:

Procurement → Suppliers
```

Requirements:

- Use existing ERP styling.
- Clear destination name.
- Show module hierarchy.
- Clicking opens the validated ERP destination.
- Do not automatically redirect users without interaction.

If multiple relevant destinations exist, show multiple suggestions.

# 8. Direct Navigation Requests

Support requests such as:

> Take me to suppliers.

> Open purchase orders.

> Go to AI providers.

Expected flow:

```text id="vltuof"
User Request
      ↓
Navigation Search / AI Interpretation
      ↓
Validated Destination
      ↓
Assistant Response
      ↓
User clicks navigation action
      ↓
ERP navigates
```

Do not automatically navigate immediately after interpreting a message.

User interaction is required.

---

# 9. Navigation Guidance Requests

Support informational requests such as:

> Where do I create a supplier?

> Where can I manage AI models?

> How do I access purchase requisitions?

The assistant should:

1. Explain the location briefly.
2. Provide validated navigation action(s).

Do not provide invented menu paths.

---

# 10. Ambiguous Requests

Handle ambiguous navigation requests.

Example:

> Open reports.

If multiple destinations are relevant:

- Return the most relevant accessible options.
- Ask the user to choose when necessary.
- Do not randomly navigate.

---

# 11. Navigation Registry Integration

Integrate currently available modules/pages cleanly.

At minimum:

### AI Module

Register all completed accessible pages:

- AI Assistant
- Management Center
- Providers
- Models
- Agents
- Knowledge
- Tools
- Automation
- Monitoring
- Settings

### Procurement Module

Register existing Procurement pages based on the actual implemented ERP navigation.

Do not invent Procurement destinations.

Read the existing navigation and register only real pages.

The architecture must make future module registration easy.

---

# 12. Conversation Context

Navigation suggestions should use:

- Current user permissions
- Current module/page context
- User request
- Existing accessible navigation registry

Example:

If the user asks:

> Take me back to purchase orders

while inside Procurement,

the system should prioritize accessible Procurement → Purchase Orders.

Do not rely solely on hardcoded keyword matching.

---

# 13. Security Requirements

Mandatory:

- Never trust AI-generated URLs.
- Resolve URLs server-side.
- Validate destination IDs.
- Validate permissions before showing navigation.
- Validate permissions again when opening protected pages through normal ERP protection.
- Do not expose inaccessible pages.
- Escape navigation labels/reasons.
- Do not allow JavaScript URLs.
- Do not allow open redirects.

---

# Important Constraints

Do NOT implement:

- ERP data search.
- Database record access.
- Record modifications.
- AI tools/function calling framework.
- Autonomous navigation.
- Automatic page redirects.
- Agents.
- RAG.

This is strictly:

**AI understanding and guiding ERP navigation.**

---

# Completion Criteria

AI F7 is complete when:

- Central navigation registry exists.
- Navigation metadata is reusable.
- Accessible destinations respect permissions.
- AI understands registered ERP destinations.
- Users can ask where features are located.
- AI can suggest validated navigation actions.
- Users can click actions to navigate.
- AI cannot invent arbitrary URLs.
- No automatic navigation occurs.
- Existing modules remain unaffected.

After implementation, provide:

- Files created
- Files modified
- Registered modules/pages
- Navigation search approach
- Security validation measures
- Known limitations
